Тестовое задание для AQA стажёра в компании учи

Подготовка к работе
-------------------

Для начала работы убедитесь, что у вас установлены [node.js + npm](https://nodejs.org/en/download)

Установите зависимости проекта, выполнив команду:
```shell
npm ci
```

Запуск тестов
-------------

Запустите тесты с помощью команды:
```shell
npx playwright test
```
Просмотр отчёта локально:
```shell
npx playwright show-report
```

## CI/CD (GitHub Actions)

Тесты запускаются автоматически на каждый push и pull request в `main`
(файл `.github/workflows/playwright.yml`).

* **Ретраи:** в CI нестабильный тест перезапускается до 2 раз (`retries: 2`). Если он проходит с повторной попытки, в отчёте он получает метку **Flaky**.
* **Отчёт:** HTML-отчёт Playwright публикуется на GitHub Pages: https://freepoet63.github.io/vk-autotests/
* **Артефакты:** трейсы и скриншоты упавших тестов доступны в Actions → нужный запуск → Artifacts → `test-results`.

### Стабилизация тестов (Борьба с Flakiness)
* **Исправление Strict Mode Violations:** Локатор кнопки закрытия кук (`._UCHI_COOKIE__button`) возвращал несколько элементов на странице. Проблема решена принудительным выбором первого активного баннера через метод `.first()`.
* **Баннер cookies в CI:** Клик по баннеру выполняется с таймаутом 20 секунд и не роняет тест, если баннер не появился. Раньше в CI баннер перекрывал кнопку виджета, и тест становился нестабильным.
* **Оптимизация скорости загрузки:** В блоке `beforeEach` метод перехода на страницу `page.goto()` переведен на стратегию `{ waitUntil: 'domcontentloaded' }`. Тесты больше не ждут загрузки тяжелой графики и сторонних метрик, приступая к выполнению сразу после готовности DOM-дерева.
* **Управление таймаутами:** Таймаут выполнения каждого теста увеличен со стандартных 30 секунд до **60 секунд** (`test.setTimeout(60000)` в `beforeEach`), что обеспечивает стабильный прогон на «тяжелом» продакшн-окружении при просадках сети.
* **Корректные селекторы:** Хрупкий селектор кнопки обратной связи `[class^=btn]` заменен на уникальный и надежный дата-атрибут `[data-test="button_feedback_form"]`, заложенный разработчиками.
* **Исправление асинхронных гонок (Race Conditions):** Ожидание кнопки виджета перенесено внутрь `openWidget()` (явный `waitFor` с таймаутом 15 секунд). Список статей возвращается как `Locator`, а клик выполняется через `.first().click()` с автоожиданием, поэтому падения `TypeError: Cannot read properties of undefined (reading 'click')` устранены.

## 📈 Текущее тестовое покрытие

На данный момент успешно выполняются **3 сквозных (E2E) сценария**:

1. **`opens`** — Проверяет успешную загрузку главной страницы, прохождение баннера кук, клик по кнопке вызова виджета и физическую видимость контейнера виджета на экране.
2. **`has correct title`** — Проверяет сквозной переход: открытие виджета -> выбор первой популярной статьи -> клик по кнопке «Написать нам» -> проверку валидности заголовка формы («Связь с поддержкой»).
3. **`can navigate back to the main list`** — Проверяет логику навигации внутри виджета: переход в статью и успешный возврат на главный экран к списку популярных статей по кнопке «Назад» в хедере.
